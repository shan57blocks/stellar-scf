2.  System  overview  
The  tool  is  a  statically  pre-rendered  Next.js  application  written  in  TypeScript,  paired  with  an  
intentionally
 
thin
 
backend.
 
It
 
reads
 
account
 
and
 
protocol
 
state
 
through
 
Horizon
 
and
 
Soroban
 
RPC
 
and
 
writes
 
only
 
transactions
 
the
 
user
 
signs
 
on
 
their
 
own
 
device.
 
There
 
is
 
no
 
database,
 
no
 
user-session
 
store,
 
and
 
no
 
analytics.
  Two  Stellar  protocol  facts  determine  the  whole  execution  model:   1.  ACCOUNT_MERGE is  the  last  operation  an  account  can  perform.  It  requires  the  High  
threshold
 
and
 
fails
 
with
 ACCOUNT_MERGE_HAS_SUB_ENTRIES while  any  subentry  
remains,
 ACCOUNT_MERGE_IS_SPONSOR while  the  account  sponsors  reserves  for  
another
 
(numSponsoring  >  0),  and  ACCOUNT_MERGE_IMMUTABLE_SET permanently  
if
 
the
 AUTH_IMMUTABLE flag  is  set,  which  the  tool  must  detect  pre-flight.  2.  A  Soroban  transaction  may  contain  exactly  one  InvokeHostFunctionOp,  and  
Soroban
 
and
 
classic
 
operations
 
cannot
 
be
 
mixed
 
in
 
one
 
transaction.
 
Each
 
contract
 
call
 
is
 
therefore
 
its
 
own
 
transaction
 
with
 
its
 
own
 
sequence-number
 
bump.
  An  account  that  holds  Soroban  positions  is  closed  with  an  N+1  transaction  plan:  N  single-call  
Soroban
 
transactions
 
to
 
exit
 
positions,
 
revoke
 
allowances,
 
and
 
drain
 
contract
 
tokens,
 
followed
 
by
 
one
 
classic
 
transaction
 
(up
 
to
 
100
 
operations)
 
that
 
clears
 
the
 
remaining
 
subentries
 
and
 
performs
 
the
 
merge.
 
Because
 
the
 
steps
 
are
 
sequential
 
and
 
state-dependent,
 
the
 
tool
 
re-reads
 
on-chain
 
state
 
before
 
building
 
each
 
step,
 
which
 
makes
 
the
 
live
 
ledger
 
the
 
source
 
of
 
truth
 
and
 
the
 
whole
 
sequence
 
idempotent.
  The  trust  model  follows  from  the  tool's  purpose.  Account  closure  is  the  most  destructive  action  a  
user
 
can
 
take
 
on
 
Stellar,
 
so
 
the
 
design
 
minimizes
 
the
 
trust
 
it
 
requires.
 
The
 
user's
 
secret
 
key
 
never
 
leaves
 
the
 
client.
 
The
 
only
 
secret
 
the
 
server
 
holds
 
is
 
a
 
per-deployment
 
mediator
 
account
 
seed,
 
whose
 
sole
 
privileged
 
action
 
is
 
co-signing
 
a
 
strictly
 
shape-validated
 
two-operation
 
envelope.
 
Every
 
Soroban
 
transaction
 
is
 
checked

hardcoded,
 
network-specific
 
contract

before
 
signing,
 
and
 
the
 
full
 
plan
 
is
 
previewed

anything
 
is
 
signed.
 
The
 
tool
 
refuses
 
to
 
attempt
 
anything
 
it
 
cannot
 
complete
 
safely.

4.  Component  and  module  architecture  
The  application  is  organized  so  that  every  Stellar-touching  concern  is  an  isolated,  independently  
testable
 
module.
 
The

is
 
an
 
XState
 
v5
 
state
 
machine;
 
the
 
privileged
 
operations
 
live
 
behind
 
three
 
server
 
routes;
 
everything
 
else
 
is
 
a
 
typed
 
library
 
module.
   
      


The  library  is  laid  out  by  responsibility:   -  lib/stellar:  classic  account  audit,  the  allow-list  check,  claimable-balance  handling,  
the
 
classic
 
transaction
 
builder,
 
the
 
Horizon
 
client,
 
and
 
classic
 
pathfinding.
 -  lib/soroban:  the  RPC  client,  ScVal  constructors,  the  SEP-41  helper  set,  transaction  
simulation,
 
allowance
 
enumeration,
 
the
 
SAC
 
helper,
 
and
 
the
 
spender
 
registry.
 -  lib/adapters:  one  per-protocol  exit  module  for  Blend,  Aquarius,  Soroswap,  FxDAO,  
plus
 
the
 
position-provider
 
adapters.
 -  lib/plan:  the  plan  generator,  the  classic  operation  batcher,  plan  hydration,  the  
per-node
 
simulator,
 
the
 
plan
 
tree,
 
and
 
the
 
classic
 
orchestrator.
 -  lib/orchestrator:  the  XState  machine,  the  page-flow  machine,  the  typed  recovery  
dispatch,
 
and

state

 -  lib/multisig:  the  signer-requirement  inspector,  the  Refractor  client,  and  the

 -  lib/mediator:  the  envelope  client,  the  strict  validator,  and  the  forward  step.  -  lib/safety:  the  CEX  registry,  fee-surge  protection,  memo  enforcement,  scam-token
